# 전체 정책 규모와 수집 범위

## 확인한 규모

- 2026-08-03 정부24 대한민국 공공서비스 정보 API 조회·적재: **10,964개 레코드**
- 정부24 공식 화면 표현: 중앙부처·지자체·공공기관·교육청의 **1만여 개 혜택**
- 직접 조사하고 정밀 룰을 만든 정책: **10개**

10,964는 법률상 고유 정책 수가 아니라 해당 시점 정부24에 등록된 서비스 레코드 수다. 현금·바우처·대출뿐 아니라 교육·상담·돌봄, 기업·기관 대상, 지역별 유사 서비스도 포함한다.

## 구현한 범위

### 전체 원본: `partially_structured`

- 목록·상세·지원조건 API 전 페이지 수집
- 공식 서비스 ID, 기관, 지역성, 분야, 지원대상·내용·신청 정보 보존
- D1 검색 API, 전체 검색 화면, 사용자 파생값 기반 1차 후보 API
- 변경 해시, 동기화 이력, 사라진 서비스 비활성화

localhost D1에 10,964건을 실제 적재했다. 전국 1,655건, 지역 9,309건이며 전체 레코드가 부분 구조화 상태다.

### 일부 구조화: `partially_structured`

정부24의 나이·중위소득 구간·출산·구직·무주택 등 48개 지원조건 코드를 저장하고 사용자 파생 프로필과 비교한다. 확실한 불일치와 다른 시·도 지역 정책을 제외하고, 상위 50개 후보에 추천 이유와 추가 확인을 표시한다.

### 정밀 추천: `rule_ready`

10개 정책은 공식 원문 검수, 조건 트리, 추천 이유, 출처, 경계값 테스트가 준비됐다. 엔진은 가능·추가 확인·불충족을 계산하지만 사용자에게는 가능·추가 확인 정책만 보여준다.

## 왜 두 층으로 나누는가

모든 원본을 보존해야 잘 알려지지 않은 지역 혜택을 찾을 수 있다. 그러나 1만여 개 자연어 조건을 검수 없이 자동 확정하면 잘못된 추천이 된다. 따라서 전체 범위는 부분 구조화 후보로 제공하고, 정밀 자격 판정은 검수된 정책부터 순차 확장한다.

## 중복 처리

- 원본 레코드는 삭제하거나 이름만으로 합치지 않는다.
- `source_id + source_service_id`를 유일 키로 사용한다.
- 원본과 검수 정책은 `policy_catalog_mappings`로 연결한다.
- 중앙 정책, 지자체 추가 지원, 지역 변형은 동시에 받을 수 있으므로 자동 병합하지 않는다.
