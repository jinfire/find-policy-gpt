# 전체 정책 규모와 수집 범위

## 현재 확인된 규모

- 확인일: 2026-07-30
- 정부24 보조금24의 대한민국 공공서비스 정보 API 조회 결과: **10,968건**
- 정부24 화면 안내: 중앙부처, 지방자치단체, 공공기관, 교육청이 제공하는 **1만여 개 서비스**
- 현재 직접 조사한 정책: **10개**
- 전체 등록 서비스 대비 조사 표본: 약 **0.09%**

### 공식 출처

- [정부24 보조금24](https://www.gov.kr/portal/main)
- [대한민국 공공서비스 정보 API 변경 안내](https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000003145)
- [대한민국 공공서비스 정보 API 운영 안내](https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000004156)

## 숫자를 해석할 때 주의할 점

10,968건은 법률상 고유한 “정책”의 개수가 아니라 보조금24에 등록된 혜택·공공서비스 레코드 수다.

여기에는 다음이 함께 포함된다.

- 현금 지원과 수당
- 바우처와 현물 지원
- 정책대출과 보증
- 교육, 상담, 돌봄 등 서비스
- 개인이 아닌 기업·농림어업인·기관 대상 지원
- 중앙정부 정책
- 지방자치단체별 지역 정책
- 공공기관과 교육청 서비스
- 같은 목적이지만 지역별로 별도 등록된 유사 서비스

따라서 `등록 서비스 수`, `중복을 합친 고유 정책 수`, `개인이 신청할 수 있는 정책 수`, `룰 기반 판정이 가능한 정책 수`는 서로 다른 숫자다.

## 결정: 전체 검색과 정밀 추천을 분리한다

1만여 개 정책을 처음부터 모두 사람이 조사하고 조건 트리로 만드는 것은 MVP 범위를 벗어난다. 대신 정책 카탈로그의 수준을 나눈다.

### 1. `search_only`

공식 API에서 가져온 이름, 설명, 기관, 신청 링크를 검색할 수 있다. 아직 서비스가 자격을 판정하지 않는다.

### 2. `partially_structured`

나이, 지역, 지원 유형 등 일부 공통 조건이 정규화돼 후보 생성에 사용할 수 있다. 복잡한 조건은 공식 페이지 확인이 필요하다.

### 3. `rule_ready`

공식 원문을 사람이 검수했고 조건 트리, 혜택 변형, 예외, 테스트가 준비됐다. 엔진은 `가능 / 추가 확인 필요 / 가능성 낮음`을 모두 계산하되, 사용자에게는 `가능 / 추가 확인 필요` 결과와 이유만 제공한다.

사용자 화면에서는 각 정책의 판정 수준을 명확히 구분한다.

## 단계별 목표

### 1단계: MVP

- 전국 공통이며 수요가 높은 정책 30~50개
- 출산·육아, 청년, 취업, 주거 중심
- 모든 정책을 `rule_ready` 수준으로 제공

### 2단계: 범위 확대

- 생애주기별 주요 정책 100~300개
- 중앙정부 정책과 주요 지자체 정책
- 사용량과 신청 전환율이 높은 정책부터 정밀 룰 적용

### 3단계: 전체 카탈로그

- 보조금24 API의 1만여 개 서비스를 검색 DB로 동기화
- 신규·변경·만료 정책 자동 탐지
- 검색 결과와 정밀 추천 결과를 함께 제공
- 조회가 많거나 사용자 요청이 많은 정책을 `rule_ready`로 승격

## 중복 정책 처리

원본 서비스 레코드는 삭제하거나 임의로 합치지 않는다. 원본 ID를 유지하면서 별도의 대표 정책 그룹으로 연결한다.

```text
source_service
  ├─ 보조금24 서비스 ID
  ├─ 공식 기관
  ├─ 원본 명칭
  └─ 지역과 유효기간

canonical_policy
  ├─ 서비스에서 사용하는 대표 정책
  └─ 여러 source_service가 연결될 수 있음
```

중복 후보 판단에는 다음을 사용한다.

- 공식 서비스 ID
- 소관기관과 담당부서
- 근거 법령·조례
- 지원 목적과 지원 유형
- 대상 지역
- 신청 링크
- 유효기간

이름이 비슷하다는 이유만으로 자동 병합하지 않는다. 중앙 정책과 지자체 추가 지원처럼 동시에 받을 수 있는 별도 혜택일 수 있기 때문이다.

## DB에 필요한 추가 상태

정책별로 다음 운영 상태를 관리한다.

- `catalog_level`: search_only, partially_structured, rule_ready
- `source_service_id`: 보조금24 등 원본 시스템 ID
- `canonical_policy_id`: 대표 정책 그룹
- `rule_coverage`: 정규화된 필수 조건의 비율
- `last_synced_at`: API에서 마지막으로 동기화한 시각
- `last_verified_at`: 사람이 공식 원문을 확인한 시각
- `change_detected_at`: 원문 변경이 감지된 시각

## 결론

- 전체 등록 규모는 현재 약 1만 1천 건이다.
- 현재 10개 조사는 DB와 룰 엔진을 검증하기 위한 표본이다.
- 첫 출시에서 모든 정책을 정밀 판정하려 하지 않는다.
- 전체 정책은 검색 가능하게 수집하고, 중요한 정책부터 검수된 정밀 룰을 붙인다.
