# ADR 0004: 정부24 전체 정책의 부분 구조화 조건 매칭

- 상태: 승인
- 결정일: 2026-08-03

## 배경

정부24 10,964건을 검색만 제공하면 사용자가 정책명을 이미 알아야 하므로 “몰라서 놓치는 혜택을 없앤다”는 목표를 충분히 달성하지 못한다. 반대로 지원조건 코드와 자연어 원문만으로 모든 정책의 최종 자격을 확정하면 거주기간, 재산 산식, 세부 대상과 예외를 놓칠 수 있다.

## 결정

1. 정부24가 제공하는 48개 지원조건 코드와 연령 범위를 모두 정규화해 `source_catalog_services.eligibility_profile` JSON에 저장한다.
2. 전체 원본은 `search_only`에서 `partially_structured`로 승격한다. 사람 검수를 마친 정책만 계속 `rule_ready`로 표현한다.
3. 조건 범주 안의 선택값은 OR, 서로 다른 범주는 AND로 해석한다.
4. 연령, 선택 입력된 성별, 예상 기준 중위소득 구간처럼 입력으로 명확히 비교 가능한 조건이 불일치하면 후보에서 제외한다.
5. 장애, 한부모, 국가보훈, 질환처럼 현재 입력으로 알 수 없는 조건은 제외 사유가 아니라 `추가 확인`으로 남긴다.
6. `해당사항없음` 코드와 전체 값이 선택된 범주는 제한 없음으로 처리한다. 연령 0~120도 제한 없음으로 처리하고 120을 넘는 비정상 값은 사용하지 않는다.
7. 개인·가구 대상만 현재 추천 흐름에 포함한다. 기업·기관 대상은 별도 프로필을 만들기 전까지 제외한다.
8. 중앙행정기관·공공기관은 전국, 시군구·광역시도·교육청·지방기관은 지역 정책으로 분류한다.
9. 지역 정책은 입력한 시·도가 기관명·지원대상·요약에 확인될 때만 후보에 포함한다. 시군구 정밀 판정은 후속 질문으로 남긴다.
10. 결과에는 전체 후보 수를 보여주고 조건 일치 점수 상위 50건만 표시한다. 조회수는 숨은 정책을 밀어내지 않도록 순위에 사용하지 않는다.
11. 모든 부분 구조화 카드에 추천 이유와 “정확한 세부 선정기준은 공식 원문에서 확인” 항목을 함께 표시한다.
12. 생년월일과 실제 소득액은 브라우저에서 나이·중위소득 비율로 계산한다. 서버에는 파생값만 보내고 저장하지 않는다.

## 결과

- 잘 알려지지 않은 정책도 사용자 입력을 기준으로 먼저 찾아줄 수 있다.
- 명확한 불일치 정책과 다른 지역 정책을 제거해 전체 검색보다 후보가 줄어든다.
- 코드에 없는 조건을 숨기지 않아 자동 판정의 정확도를 과장하지 않는다.
- 10개 정밀 정책과 10,964개 1차 후보의 신뢰 수준이 화면에서 분리된다.

## 한계와 후속 작업

- 시군구와 거주기간, 특수조건은 필요한 정책에서만 후속 질문해야 한다.
- 출산·입양 코드는 정책별 인정 기간이 달라 사람 검수 전에는 최종 충족으로 볼 수 없다.
- 자연어 선정기준과 공고 기간은 정책별 검수와 버전 관리가 필요하다.
- 공식 코드 정의와 서비스 수는 [공공데이터포털 API 안내](https://www.data.go.kr/data/15113968/openapi.do)를 기준으로 재동기화한다.
