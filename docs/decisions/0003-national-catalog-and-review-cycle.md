# ADR 0003: 전국 카탈로그와 정기 검토 주기

> 전체 원본의 `search_only` 범위와 추천 화면 결정은 [ADR 0004](./0004-gov24-partial-eligibility-matching.md)에서 `partially_structured` 1차 후보로 확장됐다. 반기 검토와 `rule_ready` 승인 원칙은 유지한다.

- 상태: 승인
- 결정일: 2026-08-01

## 배경

유명한 정책 10개만 정밀 추천하면 “몰라서 놓치는 혜택을 없앤다”는 제품 목표를 달성하기 어렵다. 반대로 정부24의 1만여 개 서비스를 검수 없이 모두 신청 가능 정책으로 보여주면 잘못된 추천이 된다.

## 결정

1. 행정안전부의 대한민국 공공서비스(혜택) Open API를 전국 카탈로그의 기준 원본으로 사용한다.
2. 중앙부처·지자체·공공기관·교육청의 전체 원본은 `source_catalog_services`에 `search_only`로 보존한다.
3. 사람 검수, 조건 트리, 출처 연결, 경계값 테스트를 통과한 정책만 `rule_ready` 정밀 추천에 사용한다.
4. 사용자 화면은 `정밀 맞춤 추천`과 `전체 원문 검색`을 명확히 구분한다.
5. 룰 엔진은 불충족 상태를 내부 계산과 테스트에 유지하지만, 사용자 결과에는 `가능성 낮은 정책`을 노출하지 않는다.
6. 입력한 연 가구소득과 가구원 수로 2026년 예상 기준 중위소득 비율을 계산한다. 실제 소득인정액과 다를 수 있음을 함께 표시한다.
7. 정책과 출처의 정기 검토 월은 매년 6월과 12월이다.
8. 갱신월이 진행 중일 때는 직전 완료 주기를 최신 필수 기준으로 사용한다. 6월이 끝나면 6월 1일 이후, 12월이 끝나면 12월 1일 이후 확인 기록을 요구한다.
9. API 동기화는 공식 키가 필요한 수동 명령으로 먼저 운영한다. GitHub Actions는 매년 6월 1일과 12월 1일 품질·출처 검사를 실행한다.
10. 개발 확인 주소는 외부 비공개 배포가 아니라 localhost를 사용한다.

## 결과

- 잘 알려지지 않은 지역 정책도 원본 검색에서 찾을 수 있다.
- 정밀 판정 범위를 과장하지 않는다.
- 원본 서비스 ID를 보존해 중복·변경·삭제를 추적할 수 있다.
- 반기 검토 규칙이 코드와 CI에 동일하게 적용된다.

## 남은 운영 조건

- 공공데이터포털 일반 인증키를 `.env.local`에 넣고 최초 전체 동기화를 실행해야 실제 1만여 건이 로컬 D1에 채워진다.
- `search_only`를 `rule_ready`로 승격하는 사람 검수 책임자와 승인 절차는 별도로 운영해야 한다.
