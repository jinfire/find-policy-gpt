# ADR 0005: 명시적 질문과 단일 추천 목록

- 상태: 채택
- 결정일: 2026-08-04

## 배경

초기 10개 정책은 정밀 룰 엔진의 가능성을 확인하기 위한 POC 표본이었다. 화면에서 이 표본을 `직접 검토한 주요 정책`으로 분리하고, 정부24 10,964건을 `기본 조건 후보`로 따로 표시하자 사용자는 두 결과가 서로 다른 상품군인 것처럼 이해할 수 있었다.

정부24 구조화 조건에 충돌만 없으면 후보로 남기는 방식도 문제가 있었다. 자녀 2명에게 3자녀 이상 정책이 보였고, 경기도 거주자에게 과천·여주 등 모든 시군구 정책이 보였으며, 일반 근로자에게 교직원·사학연금 전용 정책이 노출됐다. 넓은 성인 연령 하나만 맞는 정책까지 추천하면 수백 건이 남아 사용성이 떨어졌다.

## 결정

### 결과는 하나로 합친다

- 10개 POC와 정부24 카탈로그 결과를 `맞춤 추천 정책` 한 목록으로 표시한다.
- `rule_ready`, `partially_structured`, 데이터 출처는 내부 신뢰도와 운영 검수에만 사용한다.
- 정책명을 정규화해 같은 이름 또는 포함 관계인 항목은 POC 정책을 우선하고 중복 카드를 제거한다.
- 모든 카드는 추천 이유, 추가 확인사항, 지원 내용과 공식 링크를 같은 형식으로 제공한다.

### 추론 대신 명시적 답변을 받는다

- 가구원 수와 총 자녀 수는 서로 독립적으로 직접 입력받는다.
- `둘째`나 출생 순위로 총 자녀 수를 추론하지 않는다.
- 시·도와 시·군·구를 모두 받는다. 시군구 정책은 기관명에 두 지역명이 모두 일치해야 한다.
- 입양 자녀, 현재 임신, 직업·소속, 장애, 한부모·조손, 다문화, 북한이탈주민, 국가보훈, 질병·질환을 명시적으로 받는다.
- 사학연금 가입 여부는 사립학교 교직원을 선택했을 때만 묻는다.
- 구직 여부는 직업 선택에서 파생하고, 무주택 여부는 보유 주택 수에서 파생해 중복 질문하지 않는다.

### 추천에는 구체적인 근거가 필요하다

- 명확히 불일치한 정책은 제거한다.
- 사용자 답변과 일치하는 추천 이유가 하나도 없는 정책은 제거한다.
- 연령·소득·성별처럼 넓은 인구통계 조건 하나만 맞는 정책도 제거한다.
- 자녀 수, 입양, 거주기간, 직업, 사학연금, 무주택, 특수 가구 조건처럼 구체적인 근거 하나는 단독으로도 추천에 사용할 수 있다.
- `월평균보수 N만원 미만/이하`처럼 원문에 명확한 개인 소득 상한이 있으면 본인 연소득의 월 환산값과 비교한다. 원본 연소득은 서버로 보내지 않는다.
- 정책 원문의 세부 기준을 모두 구조화한 것은 아니므로 최종 신청 가능 여부를 확정하지 않고 공식 원문 확인사항을 유지한다.

## 구현 결과

- 사용자 입력을 3단계에서 4단계로 변경했다.
- 전국 17개 시·도의 시군구 선택 목록을 추가했다.
- 자녀 수·입양·거주기간·교직원·사학연금의 명확한 원문 조건을 안전한 범위에서 추출해 필터링한다.
- 예시 프로필 `경기 여주시·34세·3인 가구·자녀 2명·일반 근로자·무주택·특수조건 없음`은 로컬 10,964건 중 58건으로 줄었다. 이 수치는 사용자 답변에 따라 달라진다.
- 원본 생년월일과 소득액은 계속 브라우저에서만 사용하고, 나이·중위소득 비율·명시적 조건값만 매칭 API로 전송하며 저장하지 않는다.

## DB 영향

이번 변경은 DB 마이그레이션을 추가하지 않는다. 기존 `eligibility_profile` JSON과 `name`, `target_text`, `criteria_text`, `provider_type`, `provider_name`을 조합해 요청 시 판정한다. 원문 조건 추출 결과를 별도 컬럼에 저장하는 것은 추출 버전 관리와 재처리 전략을 정한 뒤 진행한다.

## 한계와 후속 결정

현재 원문 전체를 의미적으로 이해한 상태는 아니다. 넓은 연령 조건만 있는 정책은 추천 목록에서 제외되므로 전체 검색에서는 찾을 수 있지만 맞춤 추천에는 나오지 않는다. 다음 단계는 남은 후보에서 가장 많이 갈리는 미확인 조건을 계산해 3~5개씩 묻는 동적 후속 질문 엔진이다.
